## Report ownership and definitions

Official IBKR Flex defines account statements, cash/FX, trades/fees and official performance sections. ibflex is only a parser. Canary provides mature brief/performance structures for reference; it is not yet our running report engine. Our code currently owns `reporting/financial_reports.py`, original white PNG rendering,09:00Asia/Shanghai scheduling, durable delivery/UNKNOWN ownership, source freshness and baseline reconciliation. Adapting Flex must not relabel the entire custom pipeline as an upstream implementation. Real-time quote/order gates continue to use SocketAPI evidence rather than delayed statements.

## Upgrade procedure

1. Read upstream release notes/security notices and compare against the pinned revision in a separate review checkout. Fetch does not authorize production activation.
2. Check license/runtime/API changes, old local patches, endpoint changes and data schema semantics. Never assume a newer wrapper changes brokerage entitlements.
3. Make scoped changes in the linked development worktree. Run scripts/run_worktree_tests.py and pre-commit gitleaks; use only isolated state/offline network.
4. Commit and integrate via Git into the approved main workspace. Back up state/identities; update cloud monitoring and Gateway deployment manifests, keeping binary artifact source identity separate.
5. Use bounded current read-only acceptance first. Test sends/trades require their own authorized finite scope; an upgrade is not permission to replay old side effects.
6. Record new pin, actual deployment evidence and unresolved limits here/ENGINEERING.md. Preserve older source/state backups until reconciliation completes.
